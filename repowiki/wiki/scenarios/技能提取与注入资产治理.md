## 工作场景
CodeWiki 技能链路：从笔记/场景聚合编译 SKILL.md，到草稿区/生效区两区制安装，到 AGENTS.md 注入治理。适用于设计 skill_creator、排查技能未生效、精简注入内容、评估技能上下文成本。

## 适用条件
改 skill_creator/skill_match/agents_md 相关代码；技能装上不触发；评估「CLI 对齐 MCP 省 token」类方案；精简 AGENTS.md 常驻内容。

## 核心 SOP
1. **技能编译素材以笔记为主、场景为辅**：笔记保留完整步骤序列，场景是聚合压缩产物。188 条笔记里流程型 0 条时，编译出的 SOP 主干必然缺失——补流程型笔记优先于改编译器。
2. **两区制**：草稿区 repowiki/skills/ 不生效，install 到 .codebuddy/skills/ 才生效；确认闸门保留，不建自动评分门控。
3. **flag_issue 反馈三坑**：page_path 必须写草稿区路径（skills/<name>/SKILL.md），写生效区路径静默失效；未知 issue_type 降级为 custom；无关闭 issue 通道。
4. **AGENTS.md 约 79% 内容由生成器托管**：直接编辑文件会被 install-hooks 冲掉；持久改动必须改模板（locales/{zh,en}.yaml 的 artifacts.agents_md.main）或常量。
5. **Skills 三级渐进披露**：元数据 name+description 始终常驻（约 100 词/个），正文仅触发时加载，references 按需读取；disable-model-invocation 与 user-invocable 语义易搞反。
6. **skill 与 MCP 工具 1:1 映射三陷阱**：常驻非零（元数据始终在上下文）；绕过 schema 校验（skill 正文无参数校验）；放弃工作流粒度（一个 skill 承载多工具协作流程才是价值）。给 agent 不建议 1:1，给人可以。
7. **skill 自动编译不存在**：全仓只有 hint 通道（build_skill_hint 契约 never compile/install/write），没有任何环境变量开关；CODEWIKI_TEAM_MEMORY_HOOK 与 CODEWIKI_RAW_TOOL_DETAIL 都不是编译开关，别改错方向。
8. **MCP 工具定义体积实测**：49 工具 88,629 字符，描述占 70%（工具级 44% + 参数级 26%）；砍工具是性价比最差的手段，先瘦身 Top 8 大工具描述。CodeBuddy 全局 MCP 默认延迟加载，「每轮常驻 22-35k token」前提存疑。

## 判断逻辑
- 技能价值在工作流粒度（多工具协作序列），不在单工具复刻。
- 常驻成本计量单位会变（schema→元数据），但不会归零。
- 文档站是宣传口径，官方文档实测优先（延迟加载结论即来自 Subagents 文档）。

## 禁忌与反模式
- 不直接编辑 AGENTS.md 托管区块（会被冲掉）。
- 不给 subagent frontmatter 写 tools: 白名单（挡掉 MCP 工具）。
- 不假设「装上即生效」——两区制下草稿区永远不生效。
- 不把环境变量名相近就当同类开关。
