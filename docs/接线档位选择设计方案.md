# 接线档位选择设计方案 v3：hook 档 / prompt 档 + 采集开关（主动沉淀固定启用）

> 状态：已实施（2026-09-20）
> 版本：v3（2026-09-20，grill-with-docs 拷问后定稿；主动沉淀升为唯一记忆写入通道）
> 相关：`docs/Hook多智能体支持设计方案.md`（家族注册表）、`docs/team-memory-hook.md`（接线文档）、
> `docs/adr/0014-distill-notes-only-channel-exclusivity.md`（通道互斥，取代 ADR-0008）、`CONTEXT.md`

## 0. v2 → v3 变化摘要

| 维度 | v2 | v3 |
|------|----|----|
| 模型 | 读侧 `wiring` × 写侧 `active_settle` 两轴正交 | **读侧 `wiring` × 采集开关 `capture`**；写侧主动沉淀**固定启用**（不再是轴） |
| 主动沉淀 | per-agent 注册表默认 + `--active-settle on\|off` 覆盖 | **恒 on**：`--active-settle` 参数删除（传入即硬报错），ACTIVE-SETTLE 协议块恒渲染 |
| 双写去重 | 原料标记 `active_settle: true` + 蒸馏条件跳过（ADR-0008） | **蒸馏无条件只产经验笔记**（ADR-0014 通道互斥），标记机制整体退役 |
| 采集 | 收尾轮保险采集（带标记）为主兜底 | **`--capture on\|off` 独立开关**（默认 on）：off 时移除 SessionEnd（trae 为 Stop）采集注册，采集→蒸馏链路整体停摆 |
| 收尾轮兜底 | 保险采集（蒸馏捞回漏网经验） | **沉淀自查**：判据 4 收尾轮检查本会话是否漏沉淀、漏了补写（不再采集全文） |
| `--status` | `active_settle` 列（默认/CLI 来源标注） | **`capture` 列**；wired-on-disk 新增 `hooks(仅SS)+settings(capture off)` 专用值 |

## 1. 问题

任务记忆有两条接线路径，但**选哪条既不由用户决定，也无处可查**；且即便接上了，**沉淀还有一整轮会话的延迟**：

- `IDE_SPECS`（`ide_config.py`）用 `wiring` 字段分档：`"hook"`（默认，拷脚本+写 settings+AGENTS.md 段）与 `"prompt"`（只写 AGENTS.md）。目前只有 `qwenwork` 是 prompt 档。
- CLI 只有 `--ide / --create-dir / --repo-path`，**没有档位参数**。
- **沉淀延迟**：hook 档的链路是"收尾采集进 `raw/`（`pending`）→ 下轮 SessionStart 才派 distill-worker 蒸馏 → 任务记忆这时才落盘"。**记忆要等下一轮会话才可见**。

| # | 缺口 | 证据 |
|---|------|------|
| G1 | 用户无选择权：想对 codebuddy 只用 AGENTS.md，或对 `verified: false` 的宿主改走 prompt 档，都做不到 | `install_hooks.py` |
| G2 | prompt 档静默少做事：SessionStart 注入的 doctrine/概览/积压/摩擦提示在 prompt 档全部丢失，共享引导段也没让 Agent 自己补 | `prompts.py` 引导段无 doctrine/overview 步 |
| G3 | 双源漂移：`hooks.yaml` 与 `IDE_SPECS` 各描述一份事实 | 两处表格 |
| G4 | prompt 档注入文件恒为 `AGENTS.md`，但各宿主自动加载的记忆文件名不同（claude 家族主读 `CLAUDE.md`）→ 哑火且无提示 | `ide_config.py` |
| G5 | 无 `--status`：无法回答"谁接了、走哪档、缺什么" | — |
| **G6** | **沉淀延迟**：任务记忆要等"下轮蒸馏"才落盘；本轮产生的经验本轮不可见、下轮开头还可能被旧记忆误导 | `distill_conversation.py` 在下轮触发 |
| **G7** | **采集断供宿主**：trae 企业版无 SessionEnd、Stop 不带 `transcript_path`；qwenwork 无 shell hook。两者的对话采集只能靠 Agent 中介，且没有"下轮零延迟"的记忆通道 | `hooks.yaml` |

## 2. 目标 / 非目标

**目标**：档位显式可选可查（CLI + MCP prompt）；档位单源（`hooks.yaml`）；**写侧及时性**（主动沉淀固定启用，任务记忆/草稿笔记当轮落盘、下轮零延迟）；**采集链路可关**（`--capture off` 后不再产新 raw、不再有补蒸馏）；换档幂等可逆；默认行为零回归。

**非目标**：不给无 hook 宿主造 hook（不做 transcript watcher）；不改 hook 脚本的注入内容形态（SessionStart 脚本零改动复用）；不新增 MCP 工具（复用 `add_task_memory` / `ingest_note` / `capture_conversation`）；不引入会话级条目对账（去重粒度 = 通道级互斥，见 ADR-0014）。

## 3. 设计

### 3.1 读侧档位 × 采集开关模型（v3 核心）

v2 的两轴正交模型（读侧 `wiring` × 写侧 `active_settle`）在 v3 收敛为：

| 轴 | 管什么 | 取值 |
|----|--------|------|
| **`wiring`（读/生命周期侧）** | 会话开始怎么拉任务/记忆/笔记、会话结束靠什么触发采集 | `hook` / `prompt`（由注册表自动判定，无手动覆盖） |
| **`capture`（采集开关）** | SessionEnd（trae 为 Stop）采集注册是否写入 | `on`（默认）/ `off` |

**写侧主动沉淀固定启用**（ADR-0014）：任务记忆唯一通道是 `add_task_memory` 直写，蒸馏固定只产经验笔记。由此：

- **`wiring=hook` + `capture=on`**（默认）= hook 会话开始拉取 + 停顿点直写 + SessionEnd 采集兜底（现状批处理 + 主动沉淀）。
- **`wiring=hook` + `capture=off`** = 主动沉淀是唯一记忆通道，采集→蒸馏链路停摆（不再产新 raw、不再有补蒸馏）。
- **`wiring=prompt` + `capture=on`** = qwenwork 标准形态（无 hook，全靠引导段 + Agent 中介采集）。

### 3.2 档位定义（读侧，不变）

| 档位 | 含义 | 产物 |
|------|------|------|
| `hook` | 宿主有 shell 生命周期事件，能拿 `transcript_path` 或有可用的 SessionStart/Stop | `<config_dir>/hooks/*.py` + settings 注册 + `distill-worker.md` + 注入文件段 |
| `prompt` | 无 hook 机制 | 仅注入文件（+ 可选宿主协议段） |

档位由注册表自动判定（支持 SessionStart 的宿主 → hook 档；不支持的 → prompt 档），`--mode` 参数已移除（传入即硬报错）。

### 3.3 主动沉淀（写侧，固定启用）

**触发 = 自然停顿点四判据 + 收尾轮强制兜底**（不做字面每轮——任务记忆追加无去重，每轮都写会把记忆灌爆并反复触发 40 条/24KB 压缩阈值）：

1. 任务里程碑达成；
2. 关键技术决策落定；
3. 用户话题明显转向；
4. **收尾轮（强制兜底，必做）——沉淀自查**：本会话是否有未沉淀的进展/决策？有则按两条路径补写。

**两条写入路径**（均为当轮落盘，下轮 `get_task_context` 即取）：

| 写入物 | 工具 | 闸门 | 依据 |
|--------|------|------|------|
| 任务记忆 | `add_task_memory` 直写 | 无闸门（追加式） | ADR-0002 |
| 通用经验笔记 | `ingest_note(status="draft")` | **确认闸门保留**（两区制，draft→confirm） | ADR-0004；禁止手写文件 |

> 延迟消除的是**可见性**而非生效：draft 落盘即可被下轮 `get_task_context` 的 `related_notes` 以 `status: draft` 展示、能确认、能参与冲突检测；但进检索语料仍需 `confirm_note`。

### 3.4 通道互斥：蒸馏固定只产笔记（ADR-0014，v3 关键取舍）

**v2 的原料标记方案（ADR-0008）退役**。主动沉淀成为任务记忆唯一通道后，标记机制失去区分对象：

- 补蒸馏路径（task_id 过滤的 catch-up）本就默认 `skip_memories=true` 只产笔记（ADR-0010），标记在该路径冗余。
- 非补蒸馏路径的存量 raw 大多采集于「主动沉淀固定开」之前，标记缺失不代表记忆已直写——标记作为"已直写"凭证不可靠。
- 单通道模型下维护标记机制（参数、frontmatter 键、解析分支、测试）没有对应收益。

**v3 方案 = 无条件 notes-only**：所有蒸馏路径（Mode A/B/C、补蒸馏、手动批量）统一只产经验笔记，`memories_written` 恒为 0，跳过以 `memories_skipped_reason: "channel_exclusive"` 显式声明。`capture_conversation` 的 `active_settle` 参数与 frontmatter 键删除；存量 raw 中的历史标记成为无害残留。

**代价（已知情接受）**：存量积压 raw 的记忆内容不再落任务记忆（只产笔记）；Agent 漏沉淀的会话失去蒸馏捞回兜底。漏报率由观察期数据（§7.3）验证，若主动沉淀遵守度不达标，可重开 capture 恢复采集链路。

### 3.5 单源：档位进 `hooks.yaml`（叠加字段已删）

`IDE_SPECS` 退化为渲染细节（保 `dir/settings/agents_dir/agent_file/format`，去 `wiring`）；`wiring` 以注册表为单源，解析顺序 `agent > family > 默认`。**`active_settle` 字段从注册表整体删除**（ADR-0014 固定启用）：

```yaml
families:
  prompt:
    config_file: null
    events: {}
    wiring: prompt
  trae:
    config_file: hooks.json
    events:
      session_start: [SessionStart]
      session_end: [Stop]      # 无 transcript_path，不用于采集，仅注释声明

agents:
  - id: qwenwork
    family: prompt
    config_dir: null            # 无仓库标记，不参与自动探测
    verified: true
    protocol: qwenwork          # 宿主专属协议段

  - id: trae
    family: trae
    config_dir: .trae
    verified: true

  - id: codebuddy
    family: claude
    config_dir: .codebuddy
    verified: true
    wiring: hook                # 显式化
```

`hook_registry.py` 保留 `wiring_of(agent_id)`、`inject_file_of(agent_id)`；`active_settle_of()` 已退役。

### 3.6 选择入口

**入口 1 — CLI**：
`codewiki install-hooks [--ide <n>] [--capture on|off] [--status] [--inject-file <p>] [--create-dir] [--repo-path <p>]`

校验硬报错（不静默降级）：

| 指定 | 宿主 | 行为 |
|------|------|------|
| （不指定档位） | 任意 | 档位由注册表自动判定：支持 SessionStart 的宿主走 hook 档，不支持的（qwenwork）走 prompt 档 |
| （不指定档位） | `verified: false` | 接线成功 + 黄色警告（家族推导未验证） |
| `--capture off` | 任意 | 移除 SessionEnd（trae 为 Stop）采集注册且不写入；SessionStart/UserPromptSubmit 保留；脚本与 distill-worker 照常拷贝 |
| `--active-settle` | 任意 | **退出码 1**：参数已移除（ADR-0014），提示改用 `--capture` |
| `--mode` | 任意 | **退出码 1**：参数已移除，档位由注册表自动判定 |

**入口 2 — MCP prompt**（免装 CLI）：`get_prompt("team-memory-hook")` 可选 `capture`；`action=status`。

**入口 3 — `--status`**（先看后选）：

```
| agent     | family | registry | wiring | capture    | wired-on-disk                          | capability gap                     |
|-----------|--------|----------|--------|------------|----------------------------------------|------------------------------------|
| codebuddy | claude | 已验证   | hook   | on(默认)   | hooks+settings                         | -                                  |
| trae      | trae   | 已验证   | hook   | on(默认)   | hooks(仅SS)+AGENTS                     | no SessionEnd -> 主动沉淀兜底       |
| qwenwork  | prompt | 已验证   | prompt | on(默认)   | AGENTS.md only                         | no auto-capture; agent-mediated    |
```

`wired-on-disk` 用 `_relative_hook_suffix` 反匹配；`registry` 列复用 `support_matrix_markdown()` 口径，保证与 README 一致。**capture off 的磁盘形态**（SessionStart 在、SessionEnd 不在）用专用值 `hooks(仅SS)+settings(capture off)` 表示，与「接线不完整」（`hooks(partial)+settings`）显式区分——不区分的话用户会误以为接线坏了去「修复」，反而把 capture off 覆盖掉。

### 3.7 能力等价表（v3：三列）

读侧缺口由条件式引导段补（见 3.8）；**写侧及时性由主动沉淀补（固定启用）**：

| 能力 | hook 档 + capture on | hook 档 + capture off | prompt 档 |
|---|---|---|---|
| 任务记忆可见延迟 | **0**（停顿点直写） | **0**（停顿点直写） | **0**（停顿点直写） |
| 活跃任务清单 + 弹框 | SessionStart 注入 | 同左 | `list_tasks` + 弹框（引导段步骤 1-3） |
| 补蒸馏 / 笔记兜底 | `pending_raw_count`（存量积压） | 无新 raw（链路停摆） | `get_task_context.pending_raw_count` |
| doctrine 正文 | SessionStart 注入 | 同左 | `query_wiki(mode="overview")`（条件式自查步） |
| 知识库概览 | SessionStart 注入 | 同左 | 同一次 overview 一并拿到 |
| 对话采集 | SessionEnd 读 transcript | **无**（主动沉淀是唯一通道） | Agent 中介（qwenwork 会话历史 API） |

### 3.8 注入文件：条件式一份

沿用既有取舍：`AGENTS.md` 是仓库级共享文件，混合档仓库不能渲染多份互相覆盖的引导段。正文写成**档位/开关无关的条件式**，Agent 自行判断。

### 3.9 采集协议：单一 `CODEWIKI-ACTIVE-SETTLE` 块

一个块吃下"沉淀"协议（v3 删除了保险采集半边）：

- 标记：`<!-- CODEWIKI-ACTIVE-SETTLE:START/END -->`（泛化取代 `CODEWIKI-QWENWORK`）。
- 正文分级：① 停顿点四判据 + `add_task_memory` 直写 + `ingest_note(draft)` + 收尾轮沉淀自查；② 宿主专属小节由 `protocol` 触发（如 qwenwork 的 `qw_query` 会话历史 API 拉取，有 API 走真实轮次、无 API 由 Agent 重建）。
- 迁移：upsert 时发现旧 `CODEWIKI-QWENWORK` 块 → 整体删除后写新块（一次）。
- 共享引导块 `TEAM-MEMORY-TASK` 的"收尾轮"步保持条件式指向本块。

### 3.10 换档 / 换开关：幂等可逆，只删自己的条目

- `hook → prompt` 必须移除我们的 hook 注册条目（复用 `_relative_hook_suffix`）；默认保留 `.py` 脚本，`--clean` 才删脚本与 `distill-worker.md`。
- `capture on → off`：移除 SessionEnd（trae 为 Stop）采集注册；`off → on`：重新写入。均只动注册条目，协议块恒在。
- 绝不整段清空 `hooks` 键、绝不删他人条目（沿用 `merge_settings_json` preserve-all 契约）。
- 重跑幂等：任意档位/开关连跑两次 = 跑一次。

### 3.11 注入文件适配（G4）

agent 级 `inject_file`（默认 `AGENTS.md`）/`inject_dir`（规则目录型，如 `.cursor/rules/`）。未核验宿主不臆断：`inject_file: null` + `inject_verified: false` 时，接线 summary 打印提示。

### 3.12 决策树（v3）

```
--status 看支持性与当前采集状态
├─ 采集完整宿主（codebuddy/claude, verified=true）
│    ├─ 满足现状批处理 ─────────► 直接接线（默认，零回归）
│    └─ 主动沉淀效果好、想停采集─► --capture off（主动沉淀固定启用）
├─ 采集断供宿主（trae 企业版 / qwenwork）
│    └─ 默认即对：档位由注册表自动判定（trae → hook 档，qwenwork → prompt 档），
│       主动沉淀兜底 ────────────────────────────────────────► 直接装，默认已对
```

## 5. 不变量

1. **零回归**：不带新参数的接线产物与今日逐字节一致（`--capture on` 显式传入亦同）。
2. **幂等**：任意档位/开关连跑两次 = 跑一次。
3. **只动自己的东西**：非 CodeWiki 内容/条目一律不动；AGENTS.md 只动标记块。
4. **不静默降级**：非法组合退出码 1 + 可执行建议；`--active-settle` 残留传入硬报错；不确定性（`verified: false`、`inject_file: null`）必须打警告。
5. **通道互斥确定性**：蒸馏不产任务是工具层不变量（ADR-0014），不是提示约束。
6. **闸门分轨**：主动沉淀不碰笔记确认闸门（两区制，ADR-0004）；任务记忆本就无闸门（ADR-0002）。
7. **不伤宿主**：沿用 hook"异常只到 stderr、退出码 0"契约。
