# 接线档位选择设计方案 v2：hook 档 / prompt 档 + 主动沉淀叠加

> 状态：设计（待评审）
> 版本：v2（2026-09-17，grill-with-docs 拷问后定稿；并入「主动沉淀」决策）
> 相关：`docs/Hook多智能体支持设计方案.md`（家族注册表）、`docs/team-memory-hook.md`（接线文档）、
> `docs/adr/0008-active-settle-deterministic-dedup.md`（双写去重）、`CONTEXT.md`（主动沉淀 / 原料标记词条）

## 0. v1 → v2 变化摘要

| 维度 | v1 | v2 |
|------|----|----|
| 模型 | 单一 `wiring` 档（读+写一锅） | **读侧 `wiring` × 写侧 `active_settle` 两轴正交** |
| prompt 档定位 | 降级档（静默少做事，G2） | **能力补齐 + 及时性反超**：主动沉淀让任务记忆"下轮零延迟"，优于 hook 档的"下轮才蒸馏" |
| 采集 | 收尾轮/SessionEnd 是唯一原料 | 保留为**漏网经验的保险采集**；主动沉淀为主通道 |
| 双写风险 | 未考虑（无主动沉淀） | **原料标记 `active_settle: true` 确定性去重**（ADR-0008） |
| 新覆盖宿主 | — | **trae 企业版**（支持本地 command hook，但无 SessionEnd、Stop 不带 transcript）与 qwenwork 同归"采集断供" |

## 1. 问题

任务记忆有两条接线路径，但**选哪条既不由用户决定，也无处可查**；且即便接上了，**沉淀还有一整轮会话的延迟**：

- `IDE_SPECS`（`ide_config.py:58-109`）用 `wiring` 字段分档：`"hook"`（默认，拷脚本+写 settings+AGENTS.md 段，`ide_config.py:385-452`）与 `"prompt"`（只写 AGENTS.md，`ide_config.py:370-383`）。目前只有 `qwenwork` 是 prompt 档（`ide_config.py:105-108`）。
- CLI 只有 `--ide / --create-dir / --repo-path`（`install_hooks.py:61-90`），**没有档位参数**。
- **沉淀延迟**：hook 档的链路是"收尾采集进 `raw/`（`pending`）→ 下轮 SessionStart 才派 distill-worker 蒸馏 → 任务记忆这时才落盘"（`task_session_start.py:363-417`、`distill_conversation.py:1190-1208`）。**记忆要等下一轮会话才可见**，对"希望本轮沉淀、下轮即取"的诉求是结构性延迟。

| # | 缺口 | 证据 |
|---|------|------|
| G1 | 用户无选择权：想对 codebuddy 只用 AGENTS.md，或对 `verified: false` 的宿主改走 prompt 档，都做不到 | `install_hooks.py:61-90` |
| G2 | prompt 档静默少做事：SessionStart 注入的 doctrine/概览/积压/摩擦提示（`task_session_start.py:229-260`、`263-297`、`363-424`）在 prompt 档全部丢失，共享引导段（`prompts.py:38-56`）也没让 Agent 自己补 | `prompts.py:40-56` 无 doctrine/overview 步 |
| G3 | 双源漂移：`hooks.yaml:63-116` 与 `IDE_SPECS` 各描述一份事实 | 两处表格 |
| G4 | prompt 档注入文件恒为 `AGENTS.md`（`ide_config.py:372`），但各宿主自动加载的记忆文件名不同（claude 家族主读 `CLAUDE.md`）→ 哑火且无提示 | `ide_config.py:372-373` |
| G5 | 无 `--status`：无法回答"谁接了、走哪档、缺什么" | — |
| **G6** | **沉淀延迟**：任务记忆要等"下轮蒸馏"才落盘；本轮产生的经验本轮不可见、下轮开头还可能被旧记忆误导 | `distill_conversation.py:1190-1208` 在下轮触发 |
| **G7** | **采集断供宿主**：trae 企业版无 SessionEnd、Stop 不带 `transcript_path`（`hooks.yaml:48-60` 已注明"采集依赖收尾轮中介补漏"）；qwenwork 无 shell hook。两者的对话采集只能靠 Agent 中介，且没有"下轮零延迟"的记忆通道 | `hooks.yaml:48-60` |

## 2. 目标 / 非目标

**目标**：档位显式可选可查（CLI + MCP prompt）；档位单源（`hooks.yaml`）；**写侧及时性**（主动沉淀让任务记忆/草稿笔记当轮落盘、下轮零延迟）；**双写去重确定性**（原料标记，不靠提示约束）；换档幂等可逆；默认行为零回归。

**非目标**：不给无 hook 宿主造 hook（不做 transcript watcher）；不改 hook 脚本的注入内容形态（SessionStart 脚本零改动复用）；不新增 MCP 工具（复用 `add_task_memory` / `ingest_note` / `capture_conversation`）；不引入会话级条目对账（去重粒度 = 会话级标记，见 ADR-0008 已知限制）。

## 3. 设计

### 3.1 两轴正交模型（v2 核心）

把 v1 的一锅 `wiring` 拆成**读侧**与**写侧**两个正交维度：

| 轴 | 管什么 | 取值 |
|----|--------|------|
| **`wiring`（读/生命周期侧）** | 会话开始怎么拉任务/记忆/笔记、会话结束靠什么触发采集 | `hook` / `prompt` / `auto` |
| **`active_settle`（写侧叠加）** | 会话中 Agent 是否在停顿点主动沉淀任务记忆 + 草稿笔记 | `on` / `off`（有注册表默认，可覆盖） |

两轴独立：**`wiring` 决定"开始怎么读、结束怎么收"，`active_settle` 决定"过程中怎么写"**。由此天然支持用户诉求的共存形态：

- **`wiring=hook` + `active_settle=on`** = hook 会话开始拉取、prompt 过程中沉淀（trae 企业版、或 codebuddy 想更及时）。
- **`wiring=hook` + `active_settle=off`** = 现状批处理（收尾采集→下轮蒸馏）。
- **`wiring=prompt` + `active_settle=on`** = qwenwork 标准形态（无 hook，全靠引导段）。

### 3.2 档位定义（读侧，不变）

| 档位 | 含义 | 产物 |
|------|------|------|
| `hook` | 宿主有 shell 生命周期事件，能拿 `transcript_path` 或有可用的 SessionStart/Stop | `<config_dir>/hooks/*.py` + settings 注册 + `distill-worker.md` + 注入文件段 |
| `prompt` | 无 hook 机制，或用户主动放弃 hook | 仅注入文件（+ 可选宿主协议段） |
| `auto` | 按注册表 + 现场证据判定（**默认 = 今日行为**） | 由判定结果决定 |

### 3.3 主动沉淀叠加（写侧）

**触发 = 自然停顿点四判据 + 收尾轮强制兜底**（不做字面每轮——任务记忆追加无去重，每轮都写会把记忆灌爆并反复触发 40 条/24KB 压缩阈值，`task_manager.py:192-194`）：

1. 任务里程碑达成；
2. 关键技术决策落定；
3. 用户话题明显转向；
4. **收尾轮（强制兜底，必做）**。

**两条写入路径**（均为当轮落盘，下轮 `get_task_context` 即取）：

| 写入物 | 工具 | 闸门 | 依据 |
|--------|------|------|------|
| 任务记忆 | `add_task_memory` 直写 | 无闸门（追加式） | ADR-0002 |
| 通用经验笔记 | `ingest_note(status="draft")` | **确认闸门保留**（两区制，draft→confirm） | ADR-0004；禁止手写文件 |

> 延迟消除的是**可见性**而非生效：draft 落盘即可被下轮 `get_task_context` 的 `related_notes` 以 `status: draft` 展示、能确认、能参与冲突检测；但进检索语料仍需 `confirm_note`。

**保险采集（保留）**：停顿点沉淀后，收尾轮仍按引导段重建 `[{role, content}]` 调 `capture_conversation`（user 消息逐字），**带 `active_settle: true` 标记**。作用有二：① 兜住 Agent 漏沉淀的通用经验（蒸馏仍能捞回成笔记）；② 让 `pending_raw_count` 等既有信号口径不变。**禁止手写 `raw/` 文件**（与 QwenWork 协议块既有约束一致，`prompts.py:58-81`）。

### 3.4 双写去重：原料标记（ADR-0008，v2 关键取舍）

**风险**：主动沉淀写了一条记忆，收尾采集又把它蒸成记忆——而 `append_task_memories_direct` 是**纯追加、无去重**（`task_manager.py:360`、`634-663`），双写即噪声。

**方案 = 原料标记 + 确定性规则**：

- `capture_conversation` 落盘的 `conv-*.md` frontmatter 新增**顶层单行键** `active_settle: true`（沉淀协议采集时声明"本会话记忆已直写"）。**必须保持顶层单行**——遵守 stdlib-only hook 的逐行扫描约束（`CONTEXT.md` "frontmatter module" 词条）。
- `distill_conversation` 见到该标记即**只产草稿笔记、跳过任务记忆生成**——规则写在工具层，不依赖任何提示词或 LLM 自觉。
- **无标记的存量行为逐字节不变**（零回归）。

**否掉的方案**：① 提示约束（把"已沉淀只出笔记"写进 prepare 的 system_prompt）——正确性押在 LLM 自觉，链路长易漂移；② 不防重靠压缩兜底——双写发生后才收敛，期间 `get_task_context` 注入双倍条目，白耗压缩阈值。详见 ADR-0008。

### 3.5 单源：档位 + 叠加进 `hooks.yaml`

`IDE_SPECS` 退化为渲染细节（保 `dir/settings/agents_dir/agent_file/format`，去 `wiring`）；`wiring` 与 `active_settle` 都以注册表为单源，解析顺序 `agent > family > 默认`：

```yaml
families:
  prompt:
    config_file: null
    events: {}
    wiring: prompt
  trae:
    config_file: hooks.json
    events:
      session_start: [SessionStart]
      session_end: [Stop]      # 无 transcript_path，不用于采集，仅注释声明
    # active_settle 默认 true（采集断供）

agents:
  - id: qwenwork
    family: prompt
    config_dir: null            # 无仓库标记，不参与自动探测
    verified: true
    protocol: qwenwork          # 宿主专属协议段
    active_settle: true         # 采集断供 → 默认开

  - id: trae
    family: trae
    config_dir: .trae
    verified: true
    active_settle: true         # 无 SessionEnd、Stop 无 transcript → 默认开

  - id: codebuddy
    family: claude
    config_dir: .codebuddy
    verified: true
    wiring: hook                # 显式化
    active_settle: false        # hook 采集完整；用户可 --active-settle on 开共存
```

`hook_registry.py` 新增 `wiring_of(agent_id)`、`inject_file_of(agent_id)`、`active_settle_of(agent_id)`（挨着现有 `family_event`，`hook_registry.py:90-106`）。

> **默认值规则**：`trae` / `qwenwork`（采集链路断供）默认 `active_settle: true`；`codebuddy` / `claude` 等 hook 宿主默认 `false`、可显式开成"prompt 写 + hook 读"共存。`active_settle: false` 的 hook 宿主 = 现状批处理，零回归。

### 3.6 选择入口

**入口 1 — CLI**：
`codewiki install-hooks [--ide <n>] [--mode hook|prompt|auto] [--active-settle on|off] [--status] [--inject-file <p>] [--clean] [--create-dir] [--repo-path <p>]`

校验硬报错（不静默降级）：

| 指定 | 宿主 | 行为 |
|------|------|------|
| `--mode hook` | 家族为 `prompt`（qwenwork） | 退出码 1：无 shell hook 机制，请用 `--mode prompt` |
| `--mode hook` | `verified: false` | 接线成功 + 黄色警告（家族推导未验证） |
| `--mode prompt` | 任意 | 不建配置目录、不拷脚本、不写 settings，只动注入文件 |
| `--mode auto` | 任意 | 与今日一致 |
| `--active-settle` | 任意 | 覆盖注册表默认；`--status` 展示生效值与来源（注册表/CLI） |

**入口 2 — MCP prompt**（免装 CLI）：`get_prompt("team-memory-hook")` 加可选 `mode` 与 `active_settle`（`prompts.py:1025-1027` 现仅有 `action`）；新增 `action=status`。

**入口 3 — `--status`**（先看后选）：

```
| agent     | family | registry | wiring | active_settle | wired-on-disk    | capability gap                     |
|-----------|--------|----------|--------|---------------|------------------|------------------------------------|
| codebuddy | claude | verified | hook   | off(默认)     | hooks+settings   | -                                  |
| trae      | trae   | verified | hook   | on(默认)      | hooks(仅SS)+AGENTS| no SessionEnd -> 保险采集+主动沉淀 |
| qwenwork  | prompt | verified | prompt | on(默认)      | AGENTS.md only   | no auto-capture; agent-mediated    |
```

`wired-on-disk` 用 `_relative_hook_suffix`（`ide_config.py:287-298`）反匹配；`registry` 列复用 `support_matrix_markdown()`（`hook_registry.py:130+`）口径，保证与 README 一致。

### 3.7 能力等价表（v2：三列）

读侧缺口由条件式引导段补（见 3.8）；**写侧及时性由主动沉淀补**：

| 能力 | hook 档（批处理） | hook 档 + 主动沉淀 | prompt 档 + 主动沉淀 |
|---|---|---|---|
| 任务记忆可见延迟 | **1 轮**（下轮蒸馏才落盘） | **0**（停顿点直写） | **0**（停顿点直写） |
| 活跃任务清单 + 弹框 | SessionStart 注入（`task_session_start.py:105-120`） | 同左 | `list_tasks` + 弹框（引导段步骤 1-3） |
| 补蒸馏 / 笔记兜底 | `pending_raw_count`（`task_session_start.py:363-417`） | 同左（标记致蒸馏只出笔记） | `get_task_context.pending_raw_count` |
| doctrine 正文 | SessionStart 注入（`229-260`） | 同左 | `query_wiki(mode="overview")`（条件式自查步） |
| 知识库概览 | SessionStart 注入（`263-297`） | 同左 | 同一次 overview 一并拿到 |
| 对话采集 | SessionEnd 读 transcript（`capture_session_end.py:14-33`） | **收尾轮保险采集**（带标记） | 收尾轮保险采集（带标记） |

关键：及时性补齐**不需要新工具**。`add_task_memory` 本就是无闸门直写（ADR-0002），`ingest_note(status="draft")` 落盘即见；主动沉淀只是把"何时调"写进协议段。

### 3.8 注入文件：条件式一份

沿用 v1 取舍：`AGENTS.md` 是仓库级共享文件（`ide_config.py:441-442`），混合档仓库不能渲染多份互相覆盖的引导段。正文写成**档位/叠加无关的条件式**，Agent 自行判断，例如：

```markdown
5. **项目定向（按条件执行）**：若本会话上下文中没有已注入的 Team Doctrine / 知识库
   概览，调用 query_wiki(mode="overview") 拉取一次；hook 档 SessionStart 已注入则跳过。
6. **主动沉淀（按条件执行）**：若本文件存在 CODEWIKI-ACTIVE-SETTLE 块，按其停顿点四判据
   直写任务记忆 / 草稿笔记并做收尾轮保险采集；否则按第 7 步的传统收尾轮采集执行。
7. **收尾采集（传统路径）**：会话收尾轮重建 [{role, content}] 调 capture_conversation。
```

### 3.9 采集协议：单一 `CODEWIKI-ACTIVE-SETTLE` 块（替代 v1 的 PROMPT-CAPTURE 计划）

一个块吃下"沉淀 + 保险采集"两半（它们是同一协议的两半，拆两块会产生"只装一半"中间态）：

- 标记：`<!-- CODEWIKI-ACTIVE-SETTLE:START/END -->`（**取代** v1 拟议的 `CODEWIKI-PROMPT-CAPTURE`，也**泛化取代**现有 `CODEWIKI-QWENWORK`，`prompts.py:58-81`）。
- 正文分级：① 停顿点四判据 + `add_task_memory` 直写 + `ingest_note(draft)`；② 收尾轮保险采集（带 `active_settle: true`）；③ 宿主专属小节由 `protocol` 触发（如 qwenwork 的 `qw_query` 会话历史 API 拉取，有 API 走真实轮次、无 API 由 Agent 重建）。
- 迁移：upsert 时发现旧 `CODEWIKI-QWENWORK` 块 → 整体删除后写新块（一次）。
- 共享引导块 `TEAM-MEMORY-TASK`（`prompts.py:38-56`）的"收尾轮"步改成条件式指向本块（见 3.8 第 6 步）。

### 3.10 换档 / 换叠加：幂等可逆，只删自己的条目

- `hook → prompt` 必须移除我们的 hook 注册条目（复用 `_relative_hook_suffix`，`ide_config.py:287-298`）；默认保留 `.py` 脚本，`--clean` 才删脚本与 `distill-worker.md`。
- `active_settle on → off`：删 `CODEWIKI-ACTIVE-SETTLE` 块、还原共享引导块收尾步为传统采集；`off → on` 反之。均只动标记块。
- 绝不整段清空 `hooks` 键、绝不删他人条目（沿用 `merge_settings_json` preserve-all 契约，`ide_config.py:197-203`）。
- 重跑幂等：任意档位/叠加连跑两次 = 跑一次。

### 3.11 注入文件适配（G4）

agent 级 `inject_file`（默认 `AGENTS.md`）/`inject_dir`（规则目录型，如 `.cursor/rules/`）。未核验宿主不臆断：`inject_file: null` + `inject_verified: false` 时，`--mode prompt` 打印提示"将通过 AGENTS.md 注入，请确认该宿主会自动加载，否则加 `--inject-file <path>`"。`--inject-file` 支持显式覆盖。

### 3.12 决策树（v2）

```
--status 看支持性与默认叠加
├─ 采集完整宿主（codebuddy/claude, verified=true）
│    ├─ 满足现状批处理 ─────────► --mode auto --active-settle off（默认）
│    └─ 想更及时（下轮零延迟）─► --active-settle on（hook 读 + prompt 写共存）
├─ 采集断供宿主（trae 企业版 / qwenwork）
│    └─ 默认即 active_settle on；trae 走 --mode hook（SessionStart 拉取 + 保险采集），
│       qwenwork 走 --mode prompt ─────────────────────────────────► 直接装，默认已对
└─ 不想在仓库留脚本/settings（团队共享仓库）► --mode prompt（+ active_settle on）
```

## 5. 不变量

1. **零回归**：`--mode auto --active-settle off` 产物与今日逐字节一致；无 `active_settle` 标记的蒸馏行为不变。
2. **幂等**：任意档位/叠加连跑两次 = 跑一次。
3. **只动自己的东西**：非 CodeWiki 内容/条目一律不动；AGENTS.md 只动标记块（`ide_config.py:328-345`）。
4. **不静默降级**：非法组合退出码 1 + 可执行建议；不确定性（`verified: false`、`inject_file: null`）必须打警告。
5. **去重确定性**：双写防护是工具层规则（原料标记），不是提示约束（ADR-0008）。
6. **闸门分轨**：主动沉淀不碰笔记确认闸门（两区制，ADR-0004）；任务记忆本就无闸门（ADR-0002）。
7. **不伤宿主**：沿用 hook"异常只到 stderr、退出码 0"契约（`docs/team-memory-hook.md`）。
