# 0009. 任务记忆从 append-only 放宽为 append + 受控降状态

日期：2026-09-18
状态：已接受

## 背景

任务记忆（`tasks/<task_id>/memories/<user>.md`）自 ADR-0001/0002 起是纯追加
（append-only）：`add_task_memory` 只在文件尾追加 `### YYYY-MM-DD HH:MM` 时间戳头
条目，任何条目写入后不再改动。这套设计换来了实现简单与 git 历史完整，但留下两个
结构性缺口：

1. **无失效语义**：「下一步做 X」后来改成「下一步做 Y」，两条都在 hot 层被
   `get_task_context` 注入——过时结论与现行结论并列，Agent 无从分辨。
2. **无写入质量门**：直写通道（主动沉淀，ADR-0008）追加无去重、无条数限流，
   停顿点判断靠 Agent 自觉，40 条/24KB 压缩阈值被流水账无谓消耗。

横向调研（mem0 的 UPDATE+history 审计、HL-Mem 的 supersedes_id 链、powercontext
的 revise 意图、TAM 的 L2 容量分级）确认「新知识推翻旧知识」是记忆系统的必备
能力，且各家的共同纪律是**降状态、不物理删**。

## 决策

任务记忆的存储纪律从「append-only」放宽为「**append + 受控降状态**」：

1. **写入仍是纯追加**：新条目照旧追加文件尾，带短条目 ID（如 `#a3f2`）。
2. **推翻走显式 supersede**：`add_task_memory` 新增可选 `supersedes` 参数（或独立
   `void_task_memory` 工具），在被推翻条目的时间戳头下插入单行标记
   `> [superseded 日期 by #eXX]`；标记后的条目注入与检索时跳过，原文保留。
3. **写入检查（write check）**：写入路径加确定性质量门——difflib 相似度去重
   （ratio > 0.85 拒绝并返回最相似条目）、每压缩窗口软上限（超限警告放行，
   fail-open 不硬拒）、返回值携带 hot 层计数。
4. **压缩优先摘退役条目**：superseded 条目是压缩价值最低的内容，优先摘出进
   archive（全文保留，可逆，不违反降状态纪律）。

## 理由

1. **难逆转且修订既有前提**：这是对 ADR-0001/0002 隐含前提（条目写入后永不改动）
   的修订，未来读者会问「为什么记忆文件里出现了改写」。不落 ADR，这个语义转变
   会在代码 review 时被当作 bug。
2. **降状态而非删除是真实取舍**：物理删最省空间，但破坏审计链——「为什么当初
   这么决定」的原文是复盘素材。HL-Mem（supersedes 链永不物理删）与 mem0
   （history 审计表）殊途同归，本仓 git 历史虽可兜底，但工作区文件内保留标记
   让「被推翻」对无 git 工具的调用方也可见。
3. **supersede 是显式声明而非自动检测**：ADR-0007 已排除自动冲突发现（Mode C
   蒸馏实测弱冲突多为误报），所以推翻必须由 Agent/用户显式声明，工程侧只做
   确定性标记与过滤。
4. **写入检查零 LLM、fail-open**：与笔记通道的确认闸门（confirm gate）分轨命名
   （见 CONTEXT.md「写入检查」词条）——防灌爆用确定性规则，防噪声知识进库用
   两段式闸门，互补不互替。

## 已知限制

- **惰性 ID 不回写**：存量条目在注入时按出现顺序补 `#e01` 序号，不回写文件；
  supersede 引用按单 ref 匹配（持久 ID 或惰性序号）。跨会话引用存量条目依赖
  注入侧序号稳定性（文件未被并发改写），撞车风险低但非零。
- **supersede 作用域仅本人文件**：跨用户推翻不可实现（注入侧按用户过滤，Agent
  无从得知他人条目）；多人协作的「共同结论被推翻」归任务描述与笔记通道。
- **写入检查是软约束**：difflib 阈值 0.85 偏保守，漏放多于误拒；软上限警告放行
  意味着不自觉的 Agent 仍可灌爆——工程侧只报数不阻断，与 fail-open 边界一致。

## 后果

- `add_task_memory` 签名扩展（`supersedes` 可选参数 + 返回值计数），`get_task_context`
  注入侧补惰性 ID 并跳过 superseded 条目，`search_task_memories` 标注退役状态。
- 压缩路径（`compact_task_memories`）候选排序调整：superseded 优先。
- `compaction_due` 布尔升级为黄/橙/红三级（条数+字节双维，按既有阈值 75%/87.5%/100%
  内插）。
- 蒸馏 prepare 提示增强：点明既有笔记若被本次对话推翻/补充可标注建议修订
  （零机制改动，为将来事件流留接口）。
- 术语「退役（retired）」与「写入检查（write check）」进 CONTEXT.md（已完成）。
- 明确不做：mem0 式无闸门自动 UPDATE/DELETE（2026-09-17 决策）、半衰期衰减
  （C11 排除）、自动冲突发现（ADR-0007）、向量检索（多次调研一致排除）。
